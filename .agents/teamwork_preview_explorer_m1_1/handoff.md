## 2. Logic Chain

### 2.1 Runtime & Scaffold Architecture
1. **Cloudflare Workers Execution Context**:
   - Cloudflare Workers execute TypeScript/JavaScript in V8 isolates without a traditional Node.js event loop or persistent file system.
   - Enabling `compatibility_flags = ["nodejs_compat"]` in `wrangler.toml` allows modern Web and Node compatibility APIs (such as `Buffer`, `crypto`, `stream`) while preserving edge performance.
   - The worker entry point must be `src/index.ts`, exporting a standard default export `{ fetch: app.fetch }` (which Hono automatically provides via `export default app`).

2. **Database & Storage Bindings**:
   - Cloudflare D1 bindings must be declared under `[[d1_databases]]` in `wrangler.toml`.
   - The binding name must be `DB` to match `PROJECT.md` (`env.DB`).
   - The migrations directory must be set to `migrations` so that `wrangler d1 migrations apply DB --local` automatically reads migration files generated by `drizzle-kit generate`.
   - Cloudflare R2 bucket bindings must be declared under `[[r2_buckets]]` with binding `R2_BUCKET` to match `PROJECT.md` (`env.R2_BUCKET`).

3. **TypeScript & Module Resolution**:
   - Workers bundle code with esbuild via Wrangler.
   - Modern bundler workflows require `moduleResolution: "Bundler"`, `module: "ESNext"`, and `target: "ES2022"`.
   - `noEmit: true` ensures TypeScript is used strictly for type checking (`tsc --noEmit`), while Wrangler/esbuild performs the actual code bundling.
   - Path aliases `"@/*": ["./src/*"]` streamline clean modular imports across routes, middleware, services, and db models.

4. **Static SPA Frontend Delivery**:
   - In FastAPI, static files were served from disk using `FileResponse`.
   - In Cloudflare Workers, there are two primary architectures:
     - **Option A (Worker Route Embedding/Asset Import)**: Bundling or reading the HTML files and serving them with `Cache-Control: no-cache` at `GET /` and `GET /admin`.
     - **Option B (Workers Static Assets `[assets]`)**: Using Wrangler's native static assets feature (`[assets] directory = "./public"`), where `env.ASSETS` can serve assets or Wrangler serves them before Worker routing.
   - To guarantee 100% compliance with `PROJECT.md` line 70-71 and `ORIGINAL_REQUEST.md` where the backend serves both `/` and `/admin` routes with custom headers, Worker routes handling `GET /` and `GET /admin` provide deterministic behavior.

5. **Windows Execution Discipline**:
   - Because Windows PowerShell restricts uncertified `.ps1` execution, all npm/wrangler scripts in the developer guide and CI documentation must specify `npm.cmd` and `npx.cmd`, or note `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`.

## 5. Caveats

1. **SMTP Delivery in Cloudflare Workers**:
   Cloudflare Workers cannot open arbitrary outbound TCP connections using Python's standard `smtplib`. When implementing `src/services/mailer.ts`, outbound emails should use an HTTP email provider API (e.g. Resend, Brevo, Mailgun) or Cloudflare Email Routing. For development (`SMTP_HOST=""`), the backend gracefully returns HTTP 503 per the original Python specification without throwing unhandled runtime errors.
2. **Local D1 State Storage**:
   Wrangler stores local D1 SQLite state in `.wrangler/state/v3/d1`. Do not commit the `.wrangler` directory to git.
3. **Database ID for D1 in Production**:
   In `wrangler.toml`, `database_id = "00000000-0000-0000-0000-000000000000"` is a placeholder for local development. For remote deployment, the actual D1 database ID generated via `npx wrangler d1 create nabd-db` must be inserted.
